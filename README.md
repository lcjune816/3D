플레이어
- 게임 특성상 모든 상호작용은 플레이어의 손, 팔을 활용하여 이루어짐 손과 닿는 오브젝트의 판정은 ray로 체크하여 제일 가까운 거리에 있는
  오브젝트와 상호작용하게 구현 팔을 늘릴떄는 시작, 끝점 기준으로 보간한 위치에 매쉬를 배치하는 형태로 진행

맵 오브젝트
- 맵 오브젝트 전체의 배치가 끝났을때는 첫번째 맵 대략 1천 5백개의 오브젝트 두번째 맵은 대략 2천개의 오브젝트가 설치가 되었다.
- 처음에는 오브젝트가 만들어질때마다 매쉬, 텍스쳐를 새로 로드하는 형태로 하였으나 부하가 심해져서 중복되는 매쉬 또는 텍스쳐가 있을경우
  추가적인 로드를 하지 않고, 처음 로드시에만 벡터에 담아 해당되는 배열 인덱스를 가지고 있다가 배열에서 랜더 시점에 꺼내쓰는 형태로 변경하였다.
- 매쉬들의 원본 데이터는 FBX 확장자로 Assmimp 라이브러리를 사용하여 불러오는 형태로 하였으나 Assimp 라이브러리를 통하여 로드시 내가 실제로
  필요없는 데이터들도 전부 불러오고있기에 로드시 시간이 오래걸리고 메모리도 그만큼 많이 잡아먹어 부하가 일어났다.
  실제로 필요한 데이터만 바이너리화 하였고 바이너리가 안된 파일은 fbx로 로드 후 바이너리화를 진행 이미 바이너리화가 되어 있을경우 해당 파일로 로드
  하는 형태로 변경 하였다.
- 여전히 오브젝트 개수가 많아 부하는 동일하였고 오브젝트들의 DrawCall을 줄이기 위해 동일한 매쉬 텍스쳐를 사용하는 정적 오브젝트들은
  인스턴싱을 하여 최적화 진행

상호작용 오브젝트
- 오브젝트 간의 서로 상호작용이 필요하여 오브젝트간에 전체 순회 비용을 줄이기 위해,
  TriggerManager를 만들어 상호작용이 필요한 오브젝트들을 담아 서로간에 참조가 바로 가능하도록 인덱스 번호를 부여하는 형태로 진행 하였다.
- 상호작용을 위한 주요 오브젝트들은 배터리, 배터리케이스, 전기 패널, 전기 기둥 등이 있다.
- 배터리 : 플레이어의 손과 충돌시 손의 위치를 따라가도록 구현
- 배터리 케이스 : 배터리와 상호작용시 배터리는 케이스 구멍의 위치에 맞게 들어가며, 배터리 케이스와 연결된 패널이 활성화 되도록 구현
- 전기 패널 : 전기 패널은 활성화 / 비활성화 상태를 가지며 활성화되어있는 패널은 플레이어의 손과 상호작용시 플레이어의 손과 팔에 전기 이펙트를
  활성화 함으로 비활성화 된 전기 패널과의 상호작응을 하여 그 전기 패널과 연결된 문, 발전기를 활성화 할 수 있도로 구현
- 전기 기둥 : 플레이어의 팔에 전기가 활성화된 상태에서 닿으면 전기 기둥에 조명이 켜지며 활성화 되었다는 표시가 된다.
  기둥이 닿은 판정은 시작점에서 끝점으로 Ray로 판정 하였다.
  팔 시작점 -> 전기 기둥이 닿은 위치를 담고 마지막으로 닿은 위치로 부터 다시 플레이어의 시작점으로 Ray를 쏘아서 추가적으로 팔에 닿은 부분이 있는지
  판정을 하였고 만약 팔에 닿은 지점이 추가적으로 생기면 팔이 꺾이는 형태로 구현을 하였다. 팔을 플레이어 이동으로 감거나 풀때는 마지막 지점으로부터
  법선 벡터를 미리 구해놓고 외적으로 내부/외부 인지 판정을하여 다시 감거나 풀 수 있게 구현
