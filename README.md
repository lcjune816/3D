# Poppy Playtime

> DirectX 11 기반으로 제작한 3D 공포 퍼즐 장르의 1인 개인 프로젝트입니다.  
> GrabPack을 이용한 상호작용, 전기 연결 퍼즐, 맵 리소스 최적화 및 보스 추적 AI를 구현했습니다.

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 장르 | 3D 공포 퍼즐 |
| 개발 인원 | 1명 |
| 개발 환경 | Visual Studio |
| 개발 언어/API | C/C++ · DirectX 11 |
| 외부 라이브러리 | Assimp · ImGui |

## 플레이어 — GrabPack 상호작용

게임의 주요 상호작용이 플레이어의 손과 팔을 통해 이루어지도록 GrabPack을 구현했습니다.

플레이어가 손을 발사하면 일정 거리 안에 있는 오브젝트를 먼저 탐색하고, 메시 단위 피킹을 통해 실제로 손이 닿은 지점을 판정하도록 구성했습니다.

팔이 늘어나는 모습은 시작점과 손의 위치 사이를 보간하고, 보간된 위치마다 원기둥 형태의 메시를 배치하여 표현했습니다.

### 구현 기능

- Ray와 메시 피킹을 이용한 상호작용 지점 판정
- 거리를 이용한 상호작용 후보의 1차 필터링
- 시작점과 끝점 보간을 이용한 팔 메시 배치
- 손과 충돌한 오브젝트의 상태 변경
- 손 회수와 상호작용 해제 처리

## 맵 및 리소스 최적화

첫 번째 맵에는 약 1,500개, 두 번째 맵에는 약 2,000개의 오브젝트가 배치되어 있어 리소스 로딩과 렌더링에 대한 최적화가 필요했습니다.

### Resource Caching

초기에는 오브젝트를 생성할 때마다 메시와 텍스처를 새로 불러와 동일한 리소스가 메모리에 반복해서 올라가는 문제가 있었습니다.

리소스를 처음 불러올 때 컨테이너에 저장하고, 이후 동일한 리소스를 사용하는 오브젝트는 저장된 리소스의 인덱스를 참조하도록 변경했습니다.

### Resource Binary

Assimp를 이용해 FBX를 직접 불러오는 과정에서 렌더링에 필요하지 않은 데이터까지 함께 처리하며 로딩 시간과 메모리 사용량이 증가했습니다.

이를 개선하기 위해 Vertex, Index, Material 등 렌더링에 필요한 데이터만 별도의 Binary 형식으로 저장했습니다. Binary 파일이 존재하면 해당 데이터를 바로 불러오고, 존재하지 않으면 FBX를 불러온 뒤 Binary 파일을 생성하도록 구성했습니다.

### Instancing

맵 오브젝트를 개별적으로 렌더링하면서 Draw Call이 증가하는 문제가 있었습니다.

동일한 메시와 텍스처를 사용하는 정적 오브젝트의 Transform을 하나로 묶고, Instancing을 이용해 한 번의 Draw Call로 여러 오브젝트를 렌더링하도록 변경했습니다.

## 상호작용 오브젝트

상호작용이 필요한 모든 오브젝트를 매번 순회하지 않도록 TriggerManager를 구현했습니다.

각 오브젝트에 연결 대상을 식별할 수 있는 인덱스를 부여하고, 상호작용 발생 시 연결된 오브젝트를 바로 참조하도록 구성했습니다.

주요 전기 퍼즐은 다음 흐름으로 동작합니다.

`Battery → Battery Case → Electronic Panel 활성화 → 문·발전기 작동`

### Battery · Battery Case

- 손과 충돌한 Battery가 손의 위치를 따라가도록 구현
- Battery가 Case에 닿으면 지정된 위치에 부착
- Battery Case와 연결된 Electronic Panel 활성화

### Electronic Panel

Electronic Panel은 활성화와 비활성화 상태를 가집니다.

활성화된 패널에 손이 닿으면 플레이어의 손과 팔에 전기 이펙트가 적용됩니다. 전기가 활성화된 팔을 다른 패널과 연결하면 해당 패널에 연결된 문이나 발전기가 작동하도록 구현했습니다.

### Electronic Pole

전기가 활성화된 팔이 Electronic Pole에 닿으면 기둥의 조명이 켜지고 활성 상태로 변경됩니다.

팔과 장애물의 충돌 지점을 저장하고, 마지막 충돌 지점부터 플레이어 방향으로 다시 Ray를 검사하여 추가 접촉 지점을 찾도록 했습니다. 접촉 지점이 추가되면 각 지점을 기준으로 팔 메시를 다시 배치하여 팔이 장애물을 감싸는 형태를 표현했습니다.

플레이어 이동에 따라 팔이 장애물에 감기거나 풀리는 상황은 충돌 지점의 Normal Vector와 이동 방향의 외적을 이용해 판정했습니다.

## 보스 추적 AI

플레이어가 보스를 바라보고 있을 때는 보스가 멈추고, 시야에서 벗어나면 플레이어를 추적하도록 구현했습니다.

플레이어의 시선 방향과 보스를 향한 방향을 내적하여 시야 범위 안에 있는지 판정했습니다. 추적 상태에서는 미리 배치한 Navigation 경로와 A* 알고리즘을 이용해 플레이어 위치까지 이동하도록 구성했습니다.

### 구현 기능

- 내적을 이용한 플레이어 시야 판정
- 시야 상태에 따른 정지와 추적 전환
- Navigation 경로 구성
- A* 알고리즘 기반 플레이어 추적
